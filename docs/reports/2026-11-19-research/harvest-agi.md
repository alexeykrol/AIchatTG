## Разбор

### AGI-01. Выбор домена без списка доменов

**Что.** Код ищет кандидатов поиском по описаниям доменов. Модель отдельно по каждой теме
отвечает «это твоя тема?» и приводит дословную цитату из реплики. Код считает голоса. Тип
вопроса модель определяет уже внутри домена. Списка доменов модель не видит.
**Где.** `analysis/src/analyze.py:1-34`, `analysis/src/selection.py:1-37,391-400`,
`analysis/README.md:83-225`; «построен заново» — `REGISTRY.md:27`.
**Зрелость.** Замер 2026-08-17: голд разбора (80 ходов) — домен верен 0.83–0.84; содержательный
голд (190) — 0.54 до правки описания, 0.88 после (`REGISTRY.md:36-49`).
**AIchatTG.** Нет: в `apps/telegram-runtime/src/assistant-domain-routing.mjs` один запрос со
списком всех доменов (`compileDomainRouterPrompt`, «Select zero to three domains»); смотрел
также `route-arbitration.mjs`, `assistant-domains.mjs`. Дал бы маршрут, не растущий с числом
доменов.
**Риски.** 7–9 вызовов на реплику, половина счёта разговора; Python-подпроцесс из Node. При
шести доменах роутер AIchatTG может быть не хуже: сравнения на одних вопросах нет.

### AGI-02. Второй спрос при отказе

**Что.** Если первый спрос не назвал домена, тем же кандидатам вопрос задаётся ещё раз,
независимо. Отказ остаётся, только если отказали оба; снятый отказ пишется в долг. Платится
только на отказах.
**Где.** `analysis/src/analyze.py:176-207`, `analysis/tests/test_second_ask.py`; почему вторым
голосом не стал поиск — `REGISTRY.md:172-218`. **Зрелость.** С тестами; отдельно не измерен.
**AIchatTG.** Нет: grep «повторн», «second ask» по `apps/telegram-runtime/src/*.mjs` пуст. Там
аналог — повторный вызов роутера при пустом ответе. Снижает ложные отказы.

### AGI-03. Правила арбитража как данные

**Что.** Правило подсчёта голосов лежит в данных: «молчание — не голос», «назначению достаточно
одного голоса», «отказ требует всеобщего молчания». У каждого правила записан недопустимый
исход для человека. Сборка падает, если правило без недопустимого исхода, набор в данных не
равен набору в коде или правило называет домен.
**Где.** `analysis/rules.json`, `analysis/tests/test_arbitration.py:167-246`.
**AIchatTG.** Частично: само правило есть в `apps/telegram-runtime/src/route-arbitration.mjs`
(оно оттуда и взято); стражей сборки в этом файле не нашёл.

### AGI-04. Описание домена как «отпечаток материала в чужой речи»

**Что.** Описание домена пишется словами, которыми человек спрашивает, а не аннотацией
содержимого. Проверено: все 40 отказов замера были законны по старому описанию — оно было у́же
пакета; после переписывания по фактическому составу доля верных выросла с 0.54 до 0.88. В
описании есть происхождение, граница «внутри / рядом / нет вовсе», политика ответа.
**Где.** `ARCHITECTURE.md:152-185` (правило — строка 166), `knowledge/domains/*/descriptor.json`,
`REGISTRY.md:384-463`. **Зрелость.** Измерено на одном домене.
**AIchatTG.** Частично: каталог с описанием, включениями, исключениями, примерами и политикой
есть (`apps/telegram-runtime/src/domains/INDEX.md`, `docs/ASSISTANT_DOMAIN_REGISTRY_V1.md`). Нет
правила письма, поля происхождения и приёма «отказ законен по описанию — чинить описание, а не
код». Для этапа 6 это инструкция эксперту.

### AGI-05. Испытание «домен — это данные»

комментариях нет ни одного имени домена; число доменов нигде не записано.
**Где.** `analysis/tests/test_domain_is_data.py`, `answer/check_answer.mjs`.
**AIchatTG.** Частично: тест с каталогом из восьми доменов описан в
`docs/ASSISTANT_DOMAIN_REGISTRY_V1.md`; тестов «имени домена нет в коде» grep по
`apps/telegram-runtime/test` не нашёл. Исполняет правило GOAL-MAP «ни одной строки кода про
конкретную книгу».

### AGI-06. Четыре домена с намеренной избыточностью

**Что.** Вместо срезов одного домена — содержательный, навигационный, организационный и
маркетинговый; материал намеренно повторяется в соседних (`CANON.md:22-47`).
**AIchatTG.** Да: шесть доменов на одном контракте, включая «о самом ассистенте». Брать нечего,

### AGI-07. Банк: один контракт пакета

**Где.** `knowledge/bank.mjs:1-60,126`, `REGISTRY.md:260-314`. **Зрелость.** Измерено:

### AGI-08. Правило ответа = формулировка + детектор + переспрос

**Что.** Каждое правило — формулировка для модели, детектор дефекта над готовым текстом,
тяжесть и действие. Правило без детектора не загружается. При критическом дефекте — один
переспрос с названным правилом и цитатой; второй дефект — громкий отказ, а не тихий выпуск.
Часть правил исполняет код: при пустом материале модель не вызывается, строку границы ставит
код. Правил семь: `no_source_no_answer`, `boundary_first`, `no_pill`, `no_unstated_claim`,
`links_from_material_only`, `cite_the_lesson`, `conditions_by_link_only`.
**Где.** `answer/rules/answer-rules.json`, `answer/src/answer.mjs:231-307`,
`answer/src/checks.mjs:55-231`.
**Зрелость.** С тестами (139 пройдено на 2026-10-09), работало во всех живых прогонах;
отрицательный эталон — настоящий июльский ответ-«пилюля» — вморожен в проверку.
**AIchatTG.** Нет: grep `foreign_link|missing_citation|pill|detector` по
`apps/telegram-runtime/src/` дал только `analyzer-spec.json` и комментарии в
`assistant-policy.mjs`; в `provider-adapter.mjs` проверки готового текста с переспросом нет.
Даёт новому ядру ответа самопроверку.
**Риски.** Детекторы лексические, фактов не проверяют; «пилюля» ловится по одной рамке; барьер
модератора при переносе выпал из ответа (`answer/README.md:276-303`).

### AGI-10. Граница и сбой — разное

**Что.** Три исхода разведены жёстко: ответ, граница, сбой. Граница двух классов: «вне
покрытия» (домена нет) и «нет в материалах» (домен есть, материала не нашлось). Причины —
закрытый список в данных; неизвестная причина — сбой.
**Где.** `answer/rules/abstention.json`, `lab/README.md:79-97`.
**AIchatTG.** Частично: различие «воздержание / сбой маршрута» и журнал дефицитов есть
(`.claude/ARCHITECTURE.md:90-93`, `database.mjs:274-288`); закрытого списка причин не искал.
Два класса границы — это этап 5: отделить промах поиска от настоящего пробела.

### AGI-11. Экземпляр: синтетик идёт тем же проводом

**Что.** Синтетик — тот же ассистент с другой записью: копия правил с заменённым текстом роли,
собственный «домен» из записи и обстоятельств сценария, собственный банк. То, что роль
скрывает, попадает в текст роли, но не в материал.
**Где.** `participant/src/instance.mjs:1-41,136-260`, `participant/src/assistant.mjs:156`.
**AIchatTG.** Частично: `apps/telegram-runtime/scripts/lib/dual-dialogue.mjs` (629 строк) делает
то же иначе — файл `role.txt` и пакет знания из записи.
**Риски.** Оба места созданы жёстко через `createAssistant` (`lab/src/dialogue.mjs:270`):
дженерик с плагином на место эксперта не поставить.

### AGI-12. Слепота синтетика в трёх слоях

**Что.** Синтетик не должен знать устройство ассистента; запрет стоит при создании участника,
при чтении записи и триггером хранилища (`participant/migrations/001_participants.sql:72-128`).

### AGI-13. Рабочее состояние: шесть правок после волны 3

**Что.** Каждая правка родилась из живого прогона. (1) Кто сказал цитату, определяет код по
месту находки, а не модель. (2) Дословность сверяется по словам, не по пробелам. (3) Закрытие
пункта не обязано повторять вид, значение и статус. (4) Экземпляр, говорящий от себя, получает
свой запрос обновления. (5) Одиночный сбой разбора поглощается повтором, отвергнутый вывод
сохраняется. (6) Сбой транспорта — известный отказ, а не неизвестный исход.
**Где.** `participant/src/agent-state.mjs:100-200`; коммиты `a0c7559`, `1ce4bfd`, `98bd72c`,
`d9b7348`, `1a695d9`, `2492ccb`; исходный дефект — `HANDOFF.md:54`.
**Зрелость.** Измерено: без (1) первый живой разговор не состоялся.
**AIchatTG.** Частично: `apps/telegram-runtime/src/assistant-working-state.mjs` (60 строк)
остался на уровне волны 3 — роль берётся из вывода модели (`:39-49`), повторов нет. Без правок
первый живой прогон двух экземпляров там, скорее всего, упрётся в те же дефекты. Перенос
ручной: файлы разошлись по форме.
