# Invariants

## Зачем этот файл

Здесь — **жёсткие правила продукта**, которые нельзя нарушать. Не стиль,
не предпочтение, не «как обычно делаем». Нарушение инварианта = баг, а не
вопрос вкуса.

Отличие от `.claude/rules/`:
- `rules/` — как работает **агент** (когда коммитить, как делегировать).
- `INVARIANTS.md` — что не должно произойти с **продуктом** (данные,
  безопасность, контракты, инварианты состояния).

Если инвариант мешает задаче — это не повод его нарушить. Это повод
открыть обсуждение и либо ослабить формулировку, либо изменить задачу.
Перед изменением инварианта — записать в `История`, чем он был вызван.

**Категории (подсказка):** `data` · `security` · `api` · `performance` ·
`concurrency` · `migration` · `compatibility` · `licensing` · `pii`

---

### INV-001: Не использовать `DROP TABLE` в миграциях

**Категория:** data / migration
**Правило:** Миграции схемы выполняются только через `ALTER`, `ADD`,
`RENAME`, `CREATE` или дополнительные таблицы. `DROP TABLE`, `TRUNCATE`,
`DELETE FROM` без `WHERE` — запрещены в коде миграций.
**Почему:** Потеря данных недопустима. Откатывать нельзя — бэкап
восстанавливает только то, что было до миграции.
**Как проверить:**
- ревью каждой миграции вручную;
- lint: `grep -rE 'DROP TABLE|TRUNCATE|DELETE FROM [^W]' apps/*/src/database.mjs`
  должен быть пустым (кроме явно прокомментированных случаев очистки
  временных/тестовых данных);
- интеграционный тест прогоняет миграцию на копии прод-данных и
  проверяет row counts до/после.

### INV-002: Никакого прямого доступа к БД или рантайму News Digest

**Категория:** security / data
**Правило:** AIchatTG не читает и не пишет БД, `.env`, Compose-сервисы
или релизные артефакты News Digest напрямую. Любая интеграция — только
через версионированный API или event-контракт, явно согласованный.
**Почему:** `AGENTS.md` (Runtime boundary) фиксирует это как границу
продукта: AIchatTG владеет своим репозиторием, контейнером, БД,
секретами и webhook-маршрутами; News Digest — источник контента для
дайджеста, не общий рантайм.
**Как проверить:** ревью PR на прямые пути/креды другого проекта в коде
или конфигурации; `infra/aichattg/docker-compose.yml` не подключает
внешние volume/сети News Digest.
**История:** зафиксировано при выделении AIchatTG в отдельный
репозиторий (2026-08).

### INV-003: Прод-изменения — только с явным подтверждением владельца

**Категория:** security / api / migration
**Правило:** Деплой, изменение webhook, внешние сообщения в Telegram,
платные вызовы модели вне обычного рабочего потока, прод-миграции и смена
секретов требуют явного подтверждения Product Owner для КОНКРЕТНОГО
изменения (SHA/переменная, сервис, объём, откат, проверка). Коммит в
`main` или локальный тест сами по себе не являются доказательством
деплоя.
**Почему:** `AGENTS.md` (Safety and releases, Integrator protocol) — это
production hard stop автономности агента; локальная работа решается
самостоятельно в пределах поставленной задачи и сохранности чужих изменений.
**Как проверить:** перед прод-действием интегратор обязан доложить:
текущий образ/SHA в проде (или `not_run`), кандидат SHA, эффект на
рантайм/конфиг, последствия отката, доказательства (`passed`/`failed`/
`not_run`/`inconclusive`).
**История:** governance изменён 2026-09-14: постоянные модульные исполнители
упразднены, работает один активный repository-root интегратор (Codex или Claude
Code). Правило подтверждения production-мутаций не изменилось.

### INV-004: Не коммитить креды, приватные данные пользователей и прод-БД

**Категория:** security / pii
**Правило:** Токены ботов, `.env`, `runtime.env`, дампы SQLite с реальными
данными пользователей — никогда не в git.
**Почему:** `AGENTS.md`; утечка токена бота — компрометация всех трёх
ботов сразу (общий процесс).
**Как проверить:** `.gitignore` покрывает `*.env`, `*.sqlite*`,
`runtime.env`; ревью диффа перед коммитом на предмет случайного `git add`
секретного файла.
**История:** —
