# Правило: Dialog Preservation

Claude Code пишет JSONL сессий в `~/.claude/projects/<encoded-cwd>/`, а
Codex — в `~/.codex/sessions/`/`archived_sessions/`. Эти служебные каталоги не
являются бессрочным архивом проекта. Перед завершением корневой задачи копируй
доступные сессии в локальную `.claude/dialogs/` и веди реестр
`.claude/dialogs/INDEX.md` через `scripts/save-dialogs.sh`.

## Поведение

- **Автоматически:** при `/finish` диалог текущей сессии сохраняется в архив (идемпотентно).
- **Явно:** если в сессии прямо сейчас что-то ценное — пользователь говорит
  `/save-dialog` или «сохрани диалог», и `scripts/save-dialogs.sh` копирует
  доступные Claude Code и текущую Codex JSONL немедленно.
- **Запись:** в `INDEX.md` строка таблицы
  `| Date | Source | File | Session | SHA-256 | Note |`. Note — 1 строка: тема
  и почему ценно; hash обновляется вместе с растущим JSONL.

## Политика по repo_access

| Режим | `.claude/dialogs/` |
|-------|--------------------|
| `private-solo` | Локально, не коммитить |
| `private-shared` | Локально, не коммитить |
| `public` | Локально, не коммитить |

Сырой архив игнорируется Git во всех режимах: диалоги могут содержать приватный
контекст и не должны попадать в репозиторий. Скрипт не удаляет архивные файлы и
не имеет retention-периода; резервное копирование диска остаётся отдельной
ответственностью владельца среды.

## Ритм анализа

Раз в месяц или квартал перечитывать `INDEX.md`, выписывать повторяющиеся паттерны и закреплять их в `methodology/draft/` (см. methodology layer). Без этого архив бесполезен.

## Не делать

- Не редактировать сами JSONL (источник истины).
- Не пересылать архив наружу автоматически.
- Не публиковать в shared/public без чистки секретов.

Глобальная версия правила: `~/.claude/rules/dialog-preservation.md`.
